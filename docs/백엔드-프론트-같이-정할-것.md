# 백엔드·프론트가 같이 정할 것

- 작성: 서현(프론트, 네플릿스) · 2026-11-06
- 기준: [LOLog-docs](https://github.com/LOLog-2026/LOLog-docs) `spec/api-spec.md`, `spec/api-dto.md` (11/6 13:46, 커밋 f207182)
- 앱 코드는 이 기준에 맞췄어요. 아래는 **명세에 아직 없거나, 답을 기다리거나, 누가 할지 정해야 하는 것**만 모았어요.
- 정해지면 LOLog-docs 명세를 먼저 고치고(CLAUDE.md 6번), 이 문서의 "정한 것" 칸을 채워 주세요.

표의 "앱은 지금"은 서버가 아무것도 안 바꿔도 앱이 어떻게 돌아가는지예요. 모두 앱이 죽지 않게 짜 두었어요.

---

## 1. 백엔드 답을 기다리는 것

| # | 무엇 | 프론트 제안 | 앱은 지금 | 정한 것 |
| --- | --- | --- | --- | --- |
| 1-1 | **만화 이미지 크기** | 세로 4칸 PNG의 가로·세로 픽셀을 고정해 알려 주기(예: 1024×4096). 응답에 `width`, `height`가 있으면 더 좋음 | 1:4 비율로 보고 자리를 잡아요(`ComicImage.kt`의 비율 값) | |
| 1-2 | **썸네일** | 명세: 썸네일 없음, 목록도 `imageUrl`. 목록이 느리면 1컷만 자른 작은 그림(`thumbnailUrl`)을 다시 얘기하기 | `imageUrl`을 받아 위쪽 첫 칸을 잘라 보여 줘요 | |
| 1-3 | **실패 재시도 한도** | 실패한 만화는 3번에 안 세서(명세) 계속 실패하면 끝없이 다시 요청할 수 있어요. 카드당 실패 5번이 넘으면 `409 COMIC_RETRY_LIMIT` | 한도가 없어요. "다시 시도" 버튼이 계속 켜져 있어요 | |
| 1-4 | **CARD_LOCKED 기준** | 명세: 고치기·지우기 둘 다 409 `CARD_LOCKED`. 그 카드의 만화가 `QUEUED`·`STORYBOARD`·`DRAWING`일 때 막는다고 보면 되는지 확인 | 만드는 중인 만화가 있으면 고치기·지우기 버튼을 끄고, 409가 오면 "만화를 만드는 중이에요" | |
| 1-5 | **COMIC_IN_PROGRESS** | 명세: 만드는 중인 만화가 있으면 409. 앱은 버튼을 꺼서 거의 안 보내요. "동시에 두 번 눌러도 하나만 생긴다"는 뜻으로 맞는지 확인 | 409가 오면 "지금 그리는 만화가 끝나면 다시 그릴 수 있어요" | |
| 1-6 | **요약(summary) 길이** | 명세: 1~200자. 앱은 이걸 카드 제목으로 써서 길면 잘려요. AI가 제목용 한 문장(30자 안팎)으로 만들어 주면 좋겠어요 | 보관함 카드에선 한 줄, 넘치면 "…" | |
| 1-7 | **글자 수 한도** | 앱은 더 짧게 막아요. 서버도 같은 숫자로 맞출지 | 화자 이름 10자 · 장소 20자 · 대사 200자 · 공백만 입력 금지 (명세는 20 · 50 · 500자) | |
| 1-8 | **만화 목록에 카드 제목** | 만화 목록 항목에 카드 `summary`(또는 `cardSummary`)를 넣어 주기. 카드를 지워도 남게 | 제목 대신 "4컷만화"라고 보여 줘요 | |
| 1-9 | **오류에 틀린 칸(`field`)** | `INVALID_REQUEST`일 때 어느 칸이 틀렸는지 | 앱이 먼저 검사해요(빈 대사, 이메일 형식, 비밀번호 규칙) | |
| 1-10 | **카드 목록에 장소·대사 수** | `CardSummary`에 `place`, `lineCount` | 녹음 날짜만 보여 줘요 | |
| 1-11 | **소셜로만 가입한 사람의 비밀번호** | 명세에 비밀번호 바꾸기·`hasPassword`가 없어요. 소셜 가입자는 소셜로만 로그인한다고 보면 되는지 | 설정의 비밀번호 줄은 아직 그대로(프론트 수정 보류) | |

코드에서는 위 1-1, 1-2, 1-8, 1-9, 1-10 칸을 `명세에 없음(제안)`이라고 표시해 두었어요(`data/remote/ApiDtos.kt`). 서버가 안 보내도 돼요.

## 2. 명세에서 정해져서 앱을 맞춘 것 (확인만)

| 무엇 | 명세 | 앱 |
| --- | --- | --- |
| 화자 기본 이름 | `Speaker.name`이 null이면 앱이 key(`화자1`, `화자2`)를 보여 줌 | 서버는 null로 두고, 앱이 순서대로 채워요 |
| 남은 만화 횟수 | `CardSummary.comicCount`는 실패한 것 빼고 셈 | 앱이 `3 - (실패 아닌 만화 수)`로 계산. 그래서 `comicRemaining` 칸은 없어도 돼요 |
| 새 카드 알림 | `CARDS_CREATED` + `recordingId`, `cardCount`. 누르면 보관함 | 그대로. 예전 제안 `NEW_CARDS`·`cardIds`는 안 써요 |
| 지워진 카드의 만화 | `cardId`가 null(푸시에선 빈 문자열) | "원래 카드는 지워졌어요" |
| 만화 이미지 주소 | 10분짜리 서명 주소, 403이면 다시 조회 | 그림을 못 받으면 만화를 다시 조회해 새 주소를 받아요. 이 주소엔 토큰을 안 붙여요 |
| 토큰 갱신 | 401 `TOKEN_EXPIRED`일 때만 | 그때만 갱신, 동시에 와도 한 번만. `INVALID_TOKEN`·`UNAUTHORIZED`는 바로 다시 로그인 |
| 비밀번호 | 8~64자, 영문·숫자 포함 | 같은 규칙으로 바로 표시 |
| 카드 고치기 | 바꾼 것만, null이면 지움 | 바꾼 화자·대사만 보내고, 지운 이름·장소는 `null` |
| 만화 요청 | 본문 없음 | 본문 없이 보내요 |
| 푸시 전 조회 | 5초마다, DONE·FAILED면 멈춤 | 5초마다 |

## 3. 알림(FCM) — 프론트가 정한 것, 서버가 지켜 줄 것

명세 3장에 없는 부분이라 프론트가 정했어요. 서버가 이대로 보내 주면 돼요.

- 알림 문구에 대화 대사를 넣지 않아요(잠금 화면에 보이니까).
- 새 카드 알림은 묶음마다 카드가 1개 이상일 때만 보내요. 0개면 안 보내요.
- 만화 실패 알림은 실패하자마자 보내요.
- 같은 폰에서 다른 계정으로 로그인하면, 같은 FCM 토큰을 새 계정으로 옮겨 주세요(`PUT /api/devices/fcm-token`). 안 그러면 이전 계정 알림이 와요.
- 로그아웃 순서: `DELETE /api/devices/fcm-token` → `POST /auth/logout`. 실패해도 앱은 폰의 토큰을 지워요.
- 앱 안에 알림 끄기 스위치는 없어요. 안드로이드 알림 설정으로 보내요.

## 4. 계정·키를 누가 만들지

이게 정해져야 앱에 FCM과 소셜 로그인을 붙일 수 있어요. **키 파일과 비밀 값은 레포에 커밋하지 않아요.**

| 무엇 | 필요한 것 | 같이 써야 하는 곳 | 담당 |
| --- | --- | --- | --- |
| Firebase 프로젝트 | 앱 패키지 `com.lolog.app` 등록, `google-services.json` | 앱(받기)과 서버(보내기, 서비스 계정 키)가 **같은 프로젝트** | 미정 |
| 구글 로그인 | OAuth 클라이언트 Android용(SHA-1) + 웹용(서버가 ID 토큰 확인) | Firebase와 같은 Google Cloud 프로젝트 추천 | 미정 |
| 카카오 로그인 | 네이티브 앱 키, 키 해시 등록, 이메일 필수 동의 | 서버는 액세스 토큰으로 사용자 확인 | 미정 |
| 네이버 로그인 | Client ID / Client Secret, 이메일 필수 동의 | 서버는 액세스 토큰으로 사용자 확인 | 미정 |
| 시험 서버 | 서버 주소, 시험용 토큰 | 앱은 `local.properties`의 `LOLOG_BASE_URL`, `LOLOG_TEST_TOKEN` | 미정 |

- 키 해시와 SHA-1은 디버그 키와 배포 키가 달라요. 팀원마다 디버그 키가 다르면 각자 등록해야 해요.
- 소셜 로그인 버튼 순서는 카카오 → 구글 → 네이버, 지금은 "준비 중"으로 막아 두었어요.

## 5. 앱 안에서 지원 님과 정할 것 (녹음 ↔ 화면)

서버와는 상관없지만 같이 정해야 하는 것이에요. 약속 파일은 `recording/RecordingController.kt`예요.

| # | 무엇 | 서현 제안 | 지금 |
| --- | --- | --- | --- |
| 5-1 | **마이크 소리 크기 값** | 녹음 화면 파형용으로 `Recording` 상태에 0~1 소리 크기(예: `level: Float`, 100ms마다)를 넣어 주기 | 파형이 흉내만 내요 |
| 5-2 | 실제 녹음 연결 | 지원 님 PR #3 머지 뒤 `AppContainer.recorder`를 `RealRecordingController`로 바꾸고, `RecordingService`를 매니페스트에 등록 | 가짜 녹음(`MockRecordingController`) |
| 5-3 | 올리기 실패 뒤 버튼 | 지금 약속엔 "다시 올리기"가 없어서 "돌아가기"만 둠. 손으로 다시 올리는 버튼이 필요하면 `retryUpload()` 추가 | 다음 녹음·다음 실행 때 자동으로 다시 올림 |
| 5-4 | 앱을 다시 켰을 때 분석 중인 녹음 | `GET /api/recordings?status=DETECTING`으로 찾아 홈 띠에 보여 주기. 누가 부를지 | 안 불러요 |
| 5-5 | `durationSec` 타입 | 명세는 Int, 녹음 코드는 Long으로 계산. JSON은 같아서 DTO를 Long으로 둠 | Long |

## 6. 우리 부탁 페이지와 명세가 다른 곳

11/5에 백엔드에 드린 "부탁 정리" 페이지와 명세가 다르게 정한 것이에요. 명세가 기준이라 앱은 명세에 맞췄어요. 부탁 페이지는 명세에 맞춰 고칠 예정이에요.

| 부탁 페이지 | 명세 |
| --- | --- |
| 새 카드 알림 `NEW_CARDS` + `cardIds` | `CARDS_CREATED` + `recordingId`, `cardCount` |
| 썸네일 `thumbnailUrl` 따로 | 없음 |
| 응답에 `width`, `height` | 없음 (1-1에서 다시 부탁) |
| 카드에 `comicRemaining` | 없음 (`comicCount`로 계산 가능) |
| 오류에 `field` | 없음 |
| 입력 오류 `VALIDATION_FAILED` | `INVALID_REQUEST` |
| 카드 지우면 `cardDeleted` | `cardId`가 null |
